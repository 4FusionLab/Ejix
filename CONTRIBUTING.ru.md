# Участие в разработке Ejix

[English](CONTRIBUTING.md) · **Русский**

Приветствуются воспроизводимые CAD-сценарии, сообщения об ошибках, документация и код. Прочитайте [руководство](docs/GUIDE.ru.md), проверьте существующие issues. Изменение модели операции лучше обсудить до реализации.

## Сообщить об ошибке

Используйте форму issue. Укажите версию Ejix или commit, полную версию Fusion, ОС, режим истории, выбранные источники, настройки результата, шаги и expected/actual. Приложите минимальную модель, которую разрешено публиковать, либо инструкцию её построения. Скриншот помогает понять внешний вид, но не заменяет геометрию и шаги воспроизведения. См. [поддержку](SUPPORT.ru.md) и [безопасность](SECURITY.ru.md).

## Внести изменение

1. Создайте отдельную ветку. Для веток Codex используйте `codex/`, для коммитов — Conventional Commits (`feat:`, `fix:`, `docs:`, `test:`, `ci:`, `chore:`).
2. Сохраняйте независимость числовой логики и настроек от `adsk`. Зависимости выполнения — только стандартная библиотека и Fusion API.
3. Сохраняйте явный список Objects, идентичность результатов каждого исходника и все извлечения до первого Cut. Не расширяйте область действия молча.
4. Выполните проверки ниже. Для изменений UI, геометрии, адаптера и жизненного цикла пройдите затронутые [CAD-сценарии](docs/VALIDATION.ru.md), когда Fusion свободен. Используйте отдельный несохранённый документ и одного CAD-оператора.
5. Обновляйте английскую и русскую документацию вместе; изменения поведения записывайте в Unreleased обеих историй изменений.
6. Откройте PR по шаблону: опишите итоговое поведение, доказательства, ограничения и невыполненные проверки.

```sh
python -m unittest discover -s tests -v
python -m compileall -q Ejix scripts tests
python scripts/check_project.py
python scripts/build.py
```

Для офлайн-инструментов используйте Python 3.12+; дополнение работает на Python Fusion. Новый синтаксис нужно проверять в заявляемых версиях Fusion. Тесты проверяют поведение и восстановление после ошибок. Офлайн-тесты не заменяют CAD-приёмку.

## Ревью и лицензия

Делайте изменения удобными для ревью и сохраняйте чужую работу. Не коммитьте конфиденциальные модели, логи с секретами, кэши, собранные архивы и резервные копии установок. Вклад распространяется по [GPL-3.0-only](LICENSE); сохраняйте совместимые уведомления об авторстве.

Соблюдайте [правила общения](CODE_OF_CONDUCT.ru.md). Текущие соглашения описаны в [архитектуре](docs/ARCHITECTURE.ru.md), [контракте UX](docs/UX.ru.md) и [процессе выпуска](docs/PUBLISHING.ru.md).
